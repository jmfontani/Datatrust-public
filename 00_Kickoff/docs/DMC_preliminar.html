Data Model Canvas

Buscador Semántico de Datasets Públicos (PFM)
Inicio: Julio 2026 | Entrega: 25 de Octubre 2026
1. Problema / Oportunidad
  • Problema: Los buscadores actuales de datasets se basan en palabras clave exactas, sin entender intención ni contexto
  • Dolor: Dificultad para encontrar datasets cuando el vocabulario del usuario difiere de las etiquetas del portal
  • Oportunidad: 113,313+ datasets en datos.gob.es con metadatos heterogéneos y baja descubribilidad
  • Contexto: Investigadores, analistas y periodistas pierden tiempo buscando fuentes de datos relevantes
  • Gap: No existe un buscador semántico específico para datos abiertos en español que combine embeddings + metadatos estructurados
2. Solución
  • Sistema: Buscador semántico con interfaz conversacional (chatbot) para datasets públicos
  • Core: Embeddings multilingües (sentence-transformers) + búsqueda híbrida (semántica + léxica)
  • Entrada: Preguntas en lenguaje natural sobre necesidades de datos
  • Salida: Ranking de datasets priorizados con explicación de relevancia, cobertura y limitaciones
  • Alcance MVP: datos.gob.es como fuente primaria, 4 casos de uso ejemplo:
      1. Despoblación rural y demografía
      2. Salud pública y medio ambiente
      3. Vivienda y turismo
      4. Educación y distribución de la renta
  • Valor diferencial: Trazabilidad completa (enlaces verificables), no genera datos inventados
3. Fuentes de Datos
  • Primaria: datos.gob.es - Catálogo Nacional de Datos Abiertos
  • API: CKAN API (JSON) - package_list, package_show, package_search
  • Endpoint: SPARQL - consultas RDF sobre metadatos DCAT-AP
  • Formato: DCAT-AP, GeoDCAT-AP
  • Metadatos: título, descripción, tema, publicador, frecuencia, licencia, cobertura geográfica/temporal, distribuciones, idioma
  • Fase 2: data.europa.eu (desactivado inicialmente)
  • Volumen: 113,313+ datasets (a mayo 2026)
4. Clientes / Grupos de Interés
  • Investigadores/académicos: Buscan datasets para papers, tesis, proyectos de investigación
  • Analistas de datos: Necesitan fuentes para informes, dashboards, análisis sectoriales
  • Periodistas/data journalists: Buscan datos para historias, verificaciones, investigaciones
  • Estudiantes: Proyectos fin de grado/máster que requieren datos reales
  • Administraciones públicas: Gestores que quieren descubrir datos de otros organismos
  • Stakeholders indirectos: EOI (tutor/evaluadores), Ministerio de Transformación Digital
5. Actividades Clave
  • Ingesta y normalización de metadatos desde CKAN API
  • Generación de embeddings semánticos
  • Indexación vectorial (pgvector)
  • Desarrollo motor búsqueda híbrida
  • Construcción API REST
  • Diseño interfaz chatbot
  • Benchmark evaluación
  • Dashboard cobertura y calidad
6. Tipo de Análisis
  • Descriptivo: Perfilado del catálogo (temas, organismos, formatos, calidad metadatos)
  • Predictivo: Modelo de ranking de relevancia - score de match entre query y dataset
  • Prescriptivo: Recomendación priorizada + sugerencias de datasets complementarios
7. KPIs
  • Precision@5
  • Recall@10
  • nDCG@10
  • MRR
  • Tiempo hasta fuentes válidas
  • % respuestas con enlaces verificables
  • % alucinaciones < 5%
  • Cobertura catálogo > 90%
8. Recursos Clave
  • Equipo: 6 personas × 200h = 1,200h totales
  • PostgreSQL + pgvector
  • Python 3.11+
  • FastAPI + Streamlit
  • Sentence-transformers
  • Docker
  • Google Workspace (EOI)
9. Coste de Implementación
  • Infraestructura: Local/Docker (coste ~0)
  • Modelo embeddings: Open source (coste ~0)
  • Horas equipo: 1,200h totales (6 personas × 200h cada una)
  • Datos: Acceso libre vía API pública
  • Coste variable: Si se usa LLM externo para enriquecimiento de metadatos
  • Total estimado: Coste principal = tiempo del equipo
10. Riesgos y Mitigaciones
  • Riesgo: Metadatos de baja calidad → Mitigación: Estrategia enriquecimiento con LLM o scraping complementario
  • Riesgo: Modelo no captura español/administrativo → Mitigación: Fallback búsqueda léxica (BM25) + ajuste fino
  • Riesgo: Alucinaciones LLM → Mitigación: Trazabilidad obligatoria, solo datasets indexados
  • Riesgo: Alcance excesivo (scope creep) → Mitigación: MVP firmado en Gate 2
  • Riesgo: Infraestructura local insuficiente → Mitigación: Muestreo inicial + escalado progresivo
11. Beneficios / Impactos
  • Para usuarios: Reducción del tiempo de búsqueda de datasets relevantes
  • Para usuarios: Descubrimiento de datasets que no habrían encontrado con búsqueda tradicional
  • Para la administración: Mayor visibilidad y reutilización de datos abiertos
  • Para EOI: Demostración de competencias en NLP, embeddings, arquitectura de datos
  • Impacto medible: Métricas de ranking comparables vs baseline (búsqueda manual en portal)
  • Replicabilidad: Arquitectura aplicable a otros catálogos CKAN (municipales, europeos)
  • Transparencia: Todo resultado trazable a fuente original verificable
